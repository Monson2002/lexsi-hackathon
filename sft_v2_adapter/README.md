# Tiny Aya Global: schema-conditioned extraction adapter (SFT v2)

A LoRA adapter for [`CohereLabs/tiny-aya-global`](https://huggingface.co/CohereLabs/tiny-aya-global) (3.35B). Input: a JSON Schema and a document. Output: one JSON object that follows the schema,
with values taken from the document and `null` for values that are not in it.
Built for the Lexsi Labs hackathon, Track 1 (fine-tuning and data curation), with CuratorKIT (data), AlignTune (training) and AuditKIT (evaluation).

**Status: no evaluation results are reported in this card yet.** They will be added when a verified run exists. Do not assume the adapter is better than the base model until then.

## Prompt format (frozen; training and evaluation use exactly this)
System message:
```
You extract structured data. Return only a single JSON object that conforms to the given JSON Schema. Use null for values that are not present in the document. Do not invent values. Do not add explanations or markdown fences.
```
User message:
```
<JSON_SCHEMA>
{ ...the JSON Schema, json.dumps(indent=2)... }
</JSON_SCHEMA>

<DOCUMENT>
...the document text...
</DOCUMENT>
```
Every schema in training is written so that all keys are required and every value may be `null`; a missing value is the explicit `null`. Dates the schema marks as `YYYY-MM-DD` must be written that way, even if the document writes them differently.

## Use
```python
import json, torch
from transformers import AutoModelForCausalLM, AutoTokenizer, BitsAndBytesConfig
from peft import PeftModel

base = "CohereLabs/tiny-aya-global"                      # gated: accept its terms on the Hub first
fp16 = not (torch.cuda.get_device_capability()[0] >= 8)  # bf16 only on Ampere or newer
dtype = torch.float16 if fp16 else torch.bfloat16
bnb = BitsAndBytesConfig(load_in_4bit=True, bnb_4bit_quant_type="nf4", bnb_4bit_use_double_quant=True, bnb_4bit_compute_dtype=dtype)
tok = AutoTokenizer.from_pretrained(base); tok.padding_side = "left"
model = AutoModelForCausalLM.from_pretrained(base, quantization_config=bnb, device_map="auto", **({"dtype": torch.float16} if fp16 else {}))
model = PeftModel.from_pretrained(model, "monson2002/tiny-aya-sft-v2-adapter").eval()

SYSTEM = "You extract structured data. Return only a single JSON object that conforms to the given JSON Schema. Use null for values that are not present in the document. Do not invent values. Do not add explanations or markdown fences."
user = f"<JSON_SCHEMA>\n{json.dumps(schema, indent=2)}\n</JSON_SCHEMA>\n\n<DOCUMENT>\n{document}\n</DOCUMENT>"
text = tok.apply_chat_template([{"role": "system", "content": SYSTEM}, {"role": "user", "content": user}], tokenize=False, add_generation_prompt=True)
ids = tok(text, return_tensors="pt", add_special_tokens=False).to(model.device)
out = model.generate(**ids, max_new_tokens=1280, do_sample=False)
print(tok.decode(out[0][ids["input_ids"].shape[1]:], skip_special_tokens=True))
```
Greedy decoding, up to 1280 new tokens (some documents need long answers; a 384-token cap cuts them off). Validate the output against your schema; the model can still produce invalid JSON.

## Training data (2,760 examples)
Synthetic or public data only; no real personal data. The gold answer is exact by construction (a record is sampled from the schema first, the document is written from it). Curated with CuratorKIT 0.1.24: schema and length gate, exact and MinHash near-duplicate removal, secrets gate (2,994 pooled, 2,832 kept, then 2,760 after a length cap and a split guard; 2,759 used in training after one further row was over 2,560 tokens).

| Source | Rows | Notes |
|---|---|---|
| Rows derived from `sujalgawas/aya-json-sft-dataset` (revision `e26e691b`, train split) | 1,433 | six document templates (invoices, tickets, contracts, clinical notes, shipping manifests, compliance audits). 1,411 of these are augmented: dates reworded (`July 26, 2017`) while the answer stays `YYYY-MM-DD`, amounts with separators, enum labels reworded, and one to three fields removed from the text with the answer set to `null`. Some of that dataset's rows were written with Qwen2.5-7B-Instruct as teacher |
| Schema-first rows built from the structure of real-world schemas in `epfl-dlab/JSONSchemaBench` (train splits) | 1,176 | field names, nesting, enums and `$defs` come from those schemas; documents and values are generated by our own code (no LLM). The dataset card says MIT; the schemas inside keep their upstream licences |
| Rows converted from `paraloq/json_data_extraction` | 151 | **licence note unresolved**: the Hub tag says Apache-2.0, the card also says "intended for research purposes only" |

Statistics of the final set: 16.9% of answer values are `null`; 15% of ISO dates appear verbatim in the document (the rest are written another way); 337 rows use `$defs`/`$ref`. No schema, field-name set or document overlaps the evaluation sets (`val`, `test`, FieldBench `test_b`, `test_c`); the check is part of the build and its result is in the project's `STATS.md`.

## Training
AlignTune 0.1.33 (TRL backend), QLoRA: 4-bit NF4 base, LoRA r=32, alpha=64, dropout 0.05, all linear layers (60,456,960 trainable parameters). Learning rate 1e-4 (cosine, 5% warmup), 2 epochs, batch 1 x gradient accumulation 16, maximum length 2,560 tokens, seed 42, fp16 on one Kaggle T4. Loss on the JSON answer only (checked on the first training example: the answer and its two end tokens are 14% of its tokens). 346 optimizer steps in 4 h 39 min.
Last logged training loss about 0.003 and mean token accuracy 0.9987 **on the training data**: the model fits its training distribution very tightly, which says nothing yet about new documents or domains.
Files in this repo: `adapter_model.safetensors`, `adapter_config.json`, `train_config.json`, `lexsi_provenance.json` (AlignTune provenance record), `train_log.txt`.

## Evaluation
Not reported yet. Planned: base model against this adapter on four splits (Sujal's `val` and `test`, and FieldBench `test_b` for unseen domains and `test_c` for real documents), with AuditKIT, greedy decoding and a 1280-token cap; metrics parse rate, schema validity, field F1, document exact match, null accuracy and hallucination rate.
Known caveat for any in-domain number: about 78 to 81% of the answer string values in `val` and `test` also occur in the training answers, so those two splits flatter the model; judge generalisation on FieldBench.

## Limitations
- The training documents are synthetic and template-like; real documents (OCR noise, long text, tables) are much harder, and the adapter has not been shown to handle them.
- The model can echo schema fragments, drop required keys or break the schema on documents unlike its training data; always validate its output.
- Inherits the base model's licence and limitations. The base model is released under CC-BY-NC-4.0 (non-commercial), so this adapter is shared under the same licence. The paraloq licence note above applies to part of the training data.
